### 实验 B 实际性能与资源

以下数据摘自原 B 报告和保存的评估，并在本轮只读核对；不是本次新测量。测试素材 ID MUXL6QI4AJIAG，VP9/MP4、3840×2160、13.821 秒、828 帧；实际 Eagle 运行时为 Node 16.17.1 / Chrome 108.0.5359.215。缓存为 1280×720 JPEG、q=3、按逐帧 PTS 索引。

| 指标 | 直接 MP4 | JPEG 缓存 |
| --- | ---: | ---: |
| 对比随机定位样本数 | 32 | 32 |
| 请求到数据就绪：平均 | 292.0ms | 4.3ms |
| 请求到数据就绪：P95 | 877.4ms | 4.7ms |
| 请求到刷新机会：平均 | 300.1ms | 13.8ms |
| 请求到刷新机会：P95 | 888.7ms | 14.0ms |

- 首次直接模式基线另为 16 次，数据就绪平均 290.2ms、P95 884.7ms。后续四块按直接→缓存→缓存→直接进行，目标一致，预热不计统计。
- 828 帧生成耗时 6.73 秒，保存记录的磁盘占用 20.23MiB，低于 256MiB 上限。原 B 验收时缓存目录已不存在，因此当时没有逐张重新核对；本轮未重新检查帧文件或生成缓存。
- 三轮脚本拖动每轮 120 次输入：直接模式完成 8/7/9 次，缓存各完成 120 次；其余直接请求被队列丢弃，不能称为显示器掉帧数。六轮停止后最后请求与最终绘制请求位置一致。
- B 原始记录共 4537 次请求，无错误、取消或证据截断；绘制序号递增。用户人工观察为直接“明显延迟”、缓存“流畅”、停止画面“符合目标且未见倒退”。人工鼠标轨迹不同，不用人工输入数量计算等条件速度比。
- 本进程 RSS 813 次采样覆盖约 6 分 40 秒，范围 202.0～254.4MiB；首/末分钟均值 228.44/228.75MiB，三轮缓存结束未连续单向增长。FFmpeg 采样峰值约 168.0MiB，活跃 ImageBitmap 峰值 1。

### 尚未验证的问题

- 像素级逐帧准确性：未与独立参考逐帧比对。40 条辅助视频帧回调中 13 条时间与请求目标帧 PTS 不一致；可能捕获前一次帧是代码时序推断，原因未专门确认，既不能证明画布错误，也不能据此证明准确。
- 长期内存稳定性、大量素材/其他编码与帧率条件、素材切换的可靠性尚未充分验证。合成 VFR 检查通过不等于真实 VFR 全覆盖。
- updateComment 未实测；长期缓存管理、正式 UI 与正式架构没有完成验收。
- 尚未发现官方原生播放位置双向同步依据；本 PoC 未实现或验证该能力，不能把未发现依据写成已证明任何实现都不可能。

### 已知实现与测量限制

- 当前缓存是 JPEG 文件，每次请求仍读文件并解码；不是全帧常驻 RAM，也未决定为最终格式。已有容量边界和安全清理，不是完整 LRU/长期缓存系统。
- 直接模式以 seeked、缓存以 JPEG 解码完成作为数据就绪点。双 rAF 只估算刷新机会，物理显示时间为 null；平均约 68 倍的数据就绪改善不等于屏幕显示速度提高 68 倍。
- 单模式随机样本只有 32 个；P95 是样本分位，不是总体延迟上界。系统文件缓存未清空，探测已读解码源文件，因此不是冷磁盘基线，不能推广到所有视频/机器。
- RSS 为本进程采样，不包含其他 Eagle/GPU 进程或系统文件缓存；可能漏峰值。FFmpeg 和插件采样不同步，不能相加为总峰值；短时未见增长不等于长期无泄漏。
- 原生新增标注后自定义插件需手动重新读取；没有标注变化监听。当前预览限制为 5～30 秒短视频、源文件 512MiB、3600 帧、单 JPEG 4MiB、帧缓存 256MiB；非方形像素、旋转视频、超 8K 输入不覆盖。
