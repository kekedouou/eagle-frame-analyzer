# S1：统一缓存画面与音频时钟专项验证

日期：2026-10-10。权限来源：用户在本对话回复“授权S1”。属于阶段 3B 的专项验证，不进入 3C 或正式开发。产品基线仍为 [product.md v1](../../product.md)，C 仍为候选架构。

## 目标与假设

验证 FFmpeg 一次视频解码能否同时产生 720p JPEG 与 PTS 索引，提取音频后能否由 Web Audio 输出时钟驱动画布；验证拖动、逐帧、暂停、恢复及严格最新目标策略。代码完成不是验证通过。

## 范围与安全

- 新原型位于 `prototypes/playback-clock/`；A/B 代码、报告及原始证据保留。
- 使用既有专用素材 MUXL6QI4AJIAG，仅接受原 B SHA256 `1482d4d245564789866a00dcd8993a3cd3154df49b92d719962762f67e051931` 匹配文件；原文件只读。
- 最多三段不超过 5 秒的合成 MP4，用编号/二进制帧标记和提示音覆盖 CFR、VFR、偏移与无声场景，使用 H.264/H.265/VP9。合成文件只存本实验目录，不导入 Eagle。
- 现有 Node/FFmpeg，无新增依赖；临时产物（包括证据）合计不超过 512 MiB；RAM 缓存数据不超过 512 MiB。只支持该实验样本列表，不把实验限额变成正式产品输入限制。
- FFmpeg 输出经受限写入层；单一生成任务、取消及超时；清理只针对经过所有权、真实路径与已知文件验证的本实验文件。
- 无素材库/标注写入、系统安装、远程仓库或原视频修改。测试插件由用户手动加载。

## 最小文件职责与运行顺序

- `manifest.json` / `index.html`：隔离 Window 入口与实验控件。
- `prepare.cjs`：样本定位、受限预处理、时间索引/音频及安全清理。
- `fixtures.cjs`：最多三段有独立预期帧标记的合成输入。
- `player.js`：音频时钟、画布、帧缓存、最新目标与测量。
- `app.js`：连接实验控件与上述模块，保存真实窗口证据；不调用素材写入 API。
- `check*.cjs`：数据、取消/延迟及本地 FFmpeg 检查；不能冒充 Eagle 测试。
- `runtime/`、`evidence/`、本机工具配置保持 Git 忽略。

先运行本地语法/单元和有限合成输入检查，再执行授权样本的预处理记录；就绪后由用户加载插件，执行真实 Window 验证并保存新证据。具体命令和本轮结果补充到 [report.md](report.md)。

## 测量与判断

- 首次等待：从收到实验加载操作到音频、索引与首帧均可用；同时分开记录素材/哈希、预处理、浏览器初始化。命中缓存另列，不与首次混合。
- 请求链：原始输入、有效目标、图像就绪、绘制提交、刷新机会分别记录；未显示/合并/过期请求和最长无更新区间一起报告。
- 每刷新周期至多提交一张目标图像；更新提交率不是物理屏幕呈现率。实际跟手与声画同步由用户观察，不伪造物理精度。
- 帧准确性：合成源中预先设计的二进制帧标记可从实际画布像素读取，与独立预期序列比对；验证首末、相邻、VFR 边界。真实素材未独立核对的部分继续标为未验证。
- 音频偏移：使用共同时间原点，记录解码后的音频首 PTS；人工检查提示音与闪光、暂停静音和恢复；内部时钟误差不等于物理声画误差。
- 注入慢解码检查严格最新目标下的更新饥饿、终止目标必达以及切换后旧结果不得绘制。
- 记录缓存字节、预算账本、插件 RSS、FFmpeg RSS 和采样范围；不能把 512 MiB 账本当作进程总内存。
- P-01～P-04 只有相应测量真实覆盖后才评估。S1 不替代全部 4K/60fps 编码、HDR/高位深、长期稳定性或 Eagle 标注竞态验收。
