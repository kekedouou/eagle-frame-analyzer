### 本轮修正与原因

1. T0漏接既有选中视频入口，现补一次只读选择快照、中文/空格路径、显式重新调用；成功载入显示来源并重置人工观察。重新载入固定为当前快照，不随Eagle后台选择漂移；当前T0准备/自动测试中不接受再次切换，结束后点击选中按钮，完整切换生命周期留T1/T2。
2. 100ms轮询仅靠焦点判断，实际未聚焦的鼠标拖动会被上一张画面时间回写；模拟负例确实复现`.9`目标被改成`.5`。现以pointer交互及未完成定位保护滑块，窗口释放/取消兜底，一次释放只提交一次最终目标。与用户偶发症状一致，但不能声称日志已唯一证明现场原因，需重验。
3. 图像读取原先只等下一次绘制才启动，持续快拖还浪费槽位预取邻帧；现输入/槽释放立即启动最新目标，拖动期间停邻帧预取，实际Canvas仍只提交最新目标。没有增加两个在途上限、512MiB预算、降低720p或绕过文件安全检查。
4. 全段预缓存为压缩JPEG，显示仍需解成像素；基线828×1280×720×4约2.84GiB，无法全部放入512MiB受管缓存。以上是保留预算下的调度修复，不把取舍解释为卡顿可接受；若宿主仍未达标，基于新分段数据提出具体变更。
5. 新日志聚合冗余通知并保留全部关键测量点，足量30秒事件预算负例通过；开始前检查剩余证据容量，保留旧失败记录。压力延迟模型修正及不可直接比较说明见计划。

### 已确认问题与调查边界

- 初始化仍强制`load('baseline')`，重开必回旧视频；`onPluginRun`在初始化忙碌时直接丢弃。旧模拟测试先等初始化完成才调用run，未覆盖该交错。

- 只读检查已安装Eagle的`resources/app.asar`：`getSelected()`委托`get({isSelected:true})`，后者从`$bodyScope.selected.slice(0)`查询并转换为Item数组；两个入口同路，没有证据支持改调用另一个或盲目重试可以修复。本机源码核对不是实际API调用。官方契约和生命周期分别见[素材API](https://developer.eagle.cool/plugin-api/api/item)、[事件API](https://developer.eagle.cool/plugin-api/api/event)。
