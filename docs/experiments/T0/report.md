## 独立画面与音频内容核对

- 另一路 ffprobe 读取原视频，1034帧的呈现时间与新索引逐项相符，源 SHA 前后保持一致。
- 三段合成素材按既有作者预期，从实际 JPEG 像素读取全部206个编号，零不匹配；没有重新生成这些输入。
- 真实 VP9 原视频独立解码，抽查102个位置含首末，并比较相邻候选；未发现反例，其中35处相邻画面过于相似，仍属不确定。不能把“未发现反例”解释为828帧唯一身份或全部像素正确。参考采用160×90 RGB抽样、保守误差诊断，JPEG有损差异不做哈希相等判断。
- PCM（解码后的音频采样数据）中两段提示音相对作者预期偏差约 +0.04ms / −0.63ms；基线音轨峰值为0，无声样本无音轨。这是缓存内容时间核对，**不是扬声器/屏幕的物理同步精度**。真实样本只有零/正音频偏移，负偏移仅模拟验证。
- 参考未生成磁盘媒体，最大同时返回像素缓冲17,539,200字节。首次准备的基线 FFmpeg 共85次RSS观察，记录峰值191,864,832字节；约100ms观察可能遗漏瞬时峰值，不代表插件总内存或 P-04 已通过。

## 必须由用户在 Eagle 执行

1. 手动加载 `tests/host/t0/manifest.json`，确认能打开且自动显示第一帧。测试页默认固定B专用视频，不读取或写入其它素材。
2. 点击“核对三段编号帧”，等待自动检查并保存证据。再分别选 H.264、H.265 有声样本，播放/暂停，观察提示音与白闪，试拖动、释放和逐帧；填写人工观察并保存。基线音轨数字静音，用它听不到声音是预期结果。
3. 选择基线视频，点击“首次准备／复用各3轮”，再点击“运行性能协议（约5分钟）”。测试时保持前台、不拖动或切换应用，显示器Hz填实际设置。正常/压力每轮分别自动存证，独立随机定位另存；完成或报错后反馈，Codex只读复核结果并继续已授权开发，无需再次批准任务范围。

缓存清理只发生于上述明确首次准备测试中的该样本，等待会话真正退出并核对所有权；不删除源或旧证据。T0保守锁/租约在意外退出后不猜测陈旧状态，如重开被拒，保留现场由Codex核查，不手动随意删除。完整异常恢复留T2。
