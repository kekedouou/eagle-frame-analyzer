# T0：阶段 4 核心风险专项

日期：2026-10-11。状态：用户已整体授权阶段 4；已取得首次 Eagle 证据，快拖未达标，本轮修复后待针对性重测。依据为 [开发计划](../../development-plan.md)、[验证协议](../../verification.md) 和架构 A-01～A-03；不改变 R/P 需求或批准的测量门槛。

## 输入与权限

- 只读使用既有 B 专用 VP9 4K/60fps 素材（ID MUXL6QI4AJIAG，SHA256 `1482d4d245564789866a00dcd8993a3cd3154df49b92d719962762f67e051931`）和 S1 已存在的 H.264/CFR/有声、H.265/VFR/音频偏移、VP9/CFR/无声三段编号帧素材；逐一核对既有指纹及独立作者预期。不遍历素材库、不重新生成或导入样本。
- 用户此前已授权向其他选中视频开放，本次明确指出 T0 缺失该入口：补齐用户显式读取当前单选 MP4（≤30秒）的测试入口，快照固定素材 ID/路径，前后核对 SHA；不写标注、不扫描库。正常性能、首次准备和编号帧协议仍使用固定基线/既有编号样本，不把任意新素材混入旧性能对比。
- 使用现有 FFmpeg/ffprobe、本机 Node 与 Eagle 内置浏览器；本机工具和输入绝对路径保存在忽略的 `tests/host/t0/config.local.json`。不新增依赖、不修改原视频或素材元数据。
- 阶段 4 整体授权覆盖既定范围内代码、文档、新隔离缓存与本地验证。真实插件加载和宿主操作由用户执行；标注写入、新样本和重要架构变更仍另按根规范处理。

## 最小实现与文件职责

- `plugin/frame-index.cjs`：纯整数 PTS、呈现顺序、VFR 时间与逐帧映射。
- `plugin/player.js`：统一画布/音频时钟、最多两个在途图像任务、一个最新待目标和有界资源释放。仅移植经审查的算法，不依赖原型源码。
- `tests/frame-index.cjs`、`tests/player.cjs`：独立预期与模拟竞态、预算、释放检查。
- `tests/support/t0-media.cjs`、`scripts/prepare-t0.cjs`、`tests/t0-media.cjs`：专项媒体准备、现有输入核对、单视频 FFmpeg、受限读取与所有权清理。这里只支持专项，不提前实现 T2 的持久库/淘汰/恢复。
- `tests/support/t0-selection.cjs`、`tests/t0-selection.cjs`：只读捕获一次 Eagle 单选素材并校验不可变快照；不调用写入 API。
- `tests/host/t0/manifest.json`、`index.html`、`app.js`：独立 Eagle 测试入口；测量/延迟开关只在此处，不进入正式产品。
- `tests/support/t0-protocol.cjs` 与测试：确定目标轨迹、统计请求终态及实际绘制提交；`scripts/check.cjs` 为默认无媒体副作用检查入口。
- `tests/support/t0-reference.cjs`、相应测试及 `scripts/verify-t0.cjs`：独立原视频/编号画面/PCM内容核对和有界本地检查证据。`tests/t0-host.cjs` 使用模拟页面核对接线、取消及退出租约，不冒充 Eagle。
- 正式插件入口及极简产品界面在 T0 通过后的 T1 建立；当前可复用核心放批准的 `plugin/`，不另建 Git 或移动 PoC。

## 新输出边界

测试插件实际根为 `tests/host/t0/`，缓存仅在其 `cache/`；实际路径须同盘、非 C、无链接/重解析。新证据只放 `verification-runs/t0-*`。目录带所有权标记；拒绝未知文件和越界清理，只删除本次登记的 T0 产物。历史 prototypes、输入、evidence 和本机配置不改动。

专项磁盘配额：缓存合计 1GiB，独立参考最多 256MiB，证据合计 128MiB、单文件最多 16MiB；总计最多 1408MiB。这些是 T0 更小的实验上限，不替代产品 5GiB 磁盘预算。播放器受管数据仍不超过 512MiB；日志另设有界容量并说明测量开销。沿用协议的插件归属进程 1.5GiB、单 FFmpeg 1GiB 观察停止线，约100ms采样不能保证捕获瞬时峰值。取消后等待真实进程/解码结束才释放和清理，不以取消回调冒充任务结束。

## 执行与判定

1. 固定代码/工具版本、输入 SHA、源规格、实际缓存路径、预算、独立预期和环境；先执行无媒体副作用的单元/模拟检查。
2. 在隔离新缓存进行实际 JPEG/PTS/PCM 准备，前后核对源 SHA。三段编号帧依作者预期检查全部206帧；原视频采用另一路独立参考核对至少100个位置及首末帧，不把内部索引自洽当作画面正确。
3. 宿主性能严格沿用 verification：正常快速拖动3×30秒、独立随机定位3×200、未命中解码注入0/25/60ms各3轮；固定种子 `0x4e564130`，目标混合往返/反转/随机，输入约120次/秒。记录每个原始输入及合并/取代/取消/失败/未完成，终点仅为画布提交，屏幕物理呈现未测。
4. 每轮30秒之后释放定位最多等待5秒，清空在途任务最多等待10秒；超时保存失败与悬挂任务，不记为成功或零延迟。0ms常态按≥55次/秒、最长无提交≤100ms、P95≤50ms判定；压力轮只检查准确、安全、有限结束并如实报告性能。
5. 真实窗口首次准备3轮、完整缓存复用3轮，从加载回调开始至完整可操作；本地准备耗时仅是分段数据，不替代 P-03。用户观察快速拖动、首末及逐帧、声音；未完成不得自动填写人工通过。

首次反馈后的重测只要求“复测正常拖动”（同种子0ms 3×30秒、独立随机3×200）及用户选中有声视频的人工拖动/播放；不默认重跑已取得的准备与编号检查。日志使用 compact-v2：聚合重复状态/取代通知，保留每次原始输入、请求身份、真实读取/解码完成、绘制和终态，时间戳不取整；仍按12MiB估算内存、16MiB单文件、128MiB总证据限额。运行前正常重测预留40MiB、完整协议预留100MiB；不足时拒绝，不删除旧证据或增额。

新调度在输入及槽位释放时立即开始最新图像工作，绘制仍仅在浏览器提供的下一次绘制机会执行；持续拖动暂不预取无关邻帧，释放后恢复，最多2真实在途/1最新待目标及512MiB不变。新增read/decode分段时长；读取时长包含路径、身份、SHA检查，不据此单独声称hash耗时。人为25/60ms现模拟已进入解码器的不可取消服务（v2），旧版在等待后可取消并几乎不填缓存，故新旧压力轮不能直接作为性能改善倍数比较；旧原始记录保留。

自动检查可修复的问题持续推进；必要宿主测试处暂停提交可运行入口和最少操作说明。T0 尚未通过时不铺开 T1。失败记录保留，只有证据显示需变更批准架构时才提出变更；不降低门槛。Git 保存代码/本地检查版本，真实关卡获验收前不建立 `phase4-t0-verified` 标签。

本地执行结果与用户待操作步骤见 [T0记录](report.md)。统一检查不生成媒体；显式 `node scripts/prepare-t0.cjs baseline h264-cfr hevc-vfr vp9-silent` 才准备新缓存，`node scripts/verify-t0.cjs reference …` 只读登记输入和缓存做独立参考，`audio …` 核对已存在PCM；`record-checks` 保存本地检查新证据。`--fresh` 会定向清除已核所有权、无租用的T0该样本缓存后重建，不作默认命令。180秒进程超时及2000帧为T0专项保护，不新增产品输入上限。
