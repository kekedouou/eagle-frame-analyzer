## 分层与任务入口

验证分三层：L1 为纯逻辑/模拟，检查状态、索引、预算和故障；L2 为隔离文件/实际媒体检查，使用现有工具和专门输入；L3 为真实 Eagle 窗口与用户人工操作。L1/L2 不能代替 L3；提交画面不能代替屏幕物理呈现，用户观察不能写成 Codex 亲自执行。

层级描述运行环境，以下五类描述测试性质，可以交叉引用但不能互相代替。下表规定执行分工；实际已运行项以 T0 及后续任务记录为准，不将表中的计划全部记为通过。

| 性质 | 检查对象 / 层级 | 执行与判断来源 |
| --- | --- | --- |
| 单元 | 纯函数、状态/请求、索引/预算规则 / L1 | Codex运行隔离自动检查，明确模拟依赖 |
| 集成 | 模块接线、文件、进程、实际媒体与输出 / L1/L2 | Codex运行获授权的本地检查；模拟Eagle接口不冒充真实宿主 |

## 公共环境、起止与请求口径

执行前固定代码提交、工具版本、Windows/Eagle/Node/Chrome、CPU/GPU/RAM、缓存磁盘和实际路径、显示器刷新率/窗口尺寸、素材身份/SHA/规格、音轨/时间原点、后台负载及核对开关。以真实 Eagle 前台窗口为性能验收环境，不用本机 Node 模拟替代。

三种状态分开：无有效插件缓存的首次生成；磁盘缓存已有但解码 RAM 重置；已明确预热的 RAM 工作集。重置内容与有限预取须记录；未清除 Windows 文件缓存就不能称操作系统冷缓存。样本顺序/种子固定，轮次间重置方式一致；不以暖缓存成绩替换冷解码成绩。

A-04采纳后，正式准备时间还包含最多64MiB压缩JPEG池的校验读取/预载；所有轮次共用原512MiB总预算。压缩字节预载不等于全部解码图像预热，完整缓存复用也不等于首次生成。T0新增有界完整协议仅改变保存编码：完整列数据无损gzip/base64、逐轮SHA和可还原核对，保持正常/压力3×30秒、独立3×200及首次/复用各3轮。每轮实际输入/丢失时间槽、终态、读取/解码起止、就绪/提交、资源与失败保留，压缩在测量窗口之后执行；记录截断/超限不通过。短对照/人工认可与正式量化验收分开，具体预算及操作见[T0计划](experiments/T0/plan.md)。

每次操作至少记录会话/库/素材代次、原始输入号及时间、操作类别、目标帧/时间、有效目标、读取/解码开始和就绪、绘制提交、刷新机会、终态与原因。类别包括拖动、释放、明确时间定位、前后逐帧和标注点击定位；正常播放的时钟采样另列，不当作鼠标定位请求。

原始输入最终分别归为已提交、已显示目标复用、被新目标取代、取消、失败或轮末仍未完成。记录同帧合并及其关联，不能双计原始输入与有效目标；复用已显示画面但没有新绘制时，记录事实，不伪造 draw 或零毫秒绘制响应。计数应能核对总输入；测试超时计失败，保存未完成数量及等待时长，不删除该轮或给未完成请求填零延迟。

每轮分别报样本数、平均/P50/P95/最大值，P95 取排序后第 `ceil(0.95N)` 个值；跨轮汇总只能补充，不能代替每轮判定。性能从原始输入处理入口计至该目标 `drawImage` 提交，包含排队；同时分记读取、解码、就绪到提交。提交、rAF 刷新机会与屏幕实际呈现不同，物理呈现未可靠测得则留空。

## P-01/P-02：正常轮、压力轮与释放

- 正常快速拖动：每样本、每约定缓存条件 **3 轮，每轮 30 秒**。固定脚本混合往返、反转和随机跳转，使目标源帧充分变化，记录不同目标比例，避免大量同帧输入制造轻负载；慢拖/静止只检查正确性和响应，不套用55次/秒门槛。计划输入频率约 120 次/秒，记录实际间隔和数量。统计窗口为首次输入到固定 30 秒窗口结束；释放请求在之后单列，不能靠延长等待稀释停顿。轮首/轮尾尚无提交的区间也计入最长无提交。
- 正常快速目标变化的每轮画面提交率 **≥55 次/秒、最长无提交≤100ms**，是用户批准的 3C 工程验收门槛。显示配置不具备约60Hz或窗口确实后台节流时，记录条件不足并重新约定环境/补测；代码导致的刷新变慢仍属测试结果，不能作为环境借口筛掉。普通播放按源帧 PTS 展示，低源帧率播放不受 55 次/秒要求，不补帧或空重绘。
- 只计真实画布提交，输入/请求/就绪数不能充当更新率；按架构每个刷新机会至多提交一个最新目标，同一刷新机会内多次提交不能累计凑更新率，另记为调度异常。同帧重复与不同帧提交分别列出；合法重复目标可以复用，不能用无新输入的重绘循环凑数。每次提交前对照最新目标/代次与请求关联，任何陈旧目标提交均失败，不以较高更新率抵消。
- 独立定位：每样本、每约定缓存条件 **3 轮，每轮 200 个固定随机目标**，逐次等待完成，避免连续同目标。逐帧/标注点击等操作类别各自报告，样本不足时保留全部结果并标明，不能借大样本拖动平均掩盖某类失败。连续脚本的 P95 只描述完成请求，必须同时报告取代比例、未完成、排队、最长无提交和人工跟手。
- 在 T0 代表样本上，另做 **0/25/60ms 解码延迟注入，各 3 轮**，每轮解码 RAM 起点一致、使用相同序列；只对真实发生的未命中解码加延迟，记录注入范围。0ms作为正常基线按P-01/P-02门槛判定；25/60ms人为压力轮检查最新目标正确、安全和有限结束，并完整报告更新率/停顿，不要求注入60ms后仍满足正常50ms门槛。压力结果不混入正常通过统计，也不能作为正常未达标的豁免。S1 对应成绩为 61.77/32.39/18.04 次/秒，完成 P95 为 8.0/6.5/7.1ms，最长无提交为 69.5/180.3/444.2ms；末次正确不等于已解决饥饿。
- 每轮释放到稳定目标后，实际画布必须准确显示该源帧并保持暂停，之后才允许播放/添加标注；记录释放输入至实际提交及有限超时结果。旧请求都须明确结束，不能留下悬挂任务。有限超时值和轨迹在 T0 执行清单固定，超时属于失败，不构成响应标准豁免。

## P-03：首次与复用

每样本 **3 次首次完整准备、3 次有效缓存复用**，保留每次结果。首次前只处理专项授权目录内该样本的插件缓存，不改源文件、不清系统缓存、不碰旧证据。复用验证不重复生成；首次与复用不合并求平均。

起点为本次 `onPluginCreate`/再次调用回调或显式读取按钮入口，包含当次初始化、选中 API、排队、读取/哈希、分析、JPEG/音频生成及浏览器初始化；终点为完整缓存/索引、音频可用、首帧提交并可操作。无音轨时明确记音频不适用。预先准备好测试输入，制作样本耗时不计入插件准备；Eagle 进入回调前的启动未测须说明，不能冒充用户点击起的完整时间。

媒体时长沿实际共同时间关系确定，保留视频/音频跨度及容器记录，不随测量成绩改分母。原 B 的 6.73 秒为生成阶段；S1 原 4K 的 7848.3ms 为 Node 准备，3650.4ms 为窗口复用，均不能替代新缓存的完整窗口 P-03。真实 HEVC 首次 2478.2ms/约10.031秒支持已测案例，不代表 4K60 全矩阵通过。

## P-04：预算、趋势与观察停止线

2026-10-15当前v5补充：准备中用户关闭应记录expected取消，不弹“验证未通过”、不标准备成功；SDK退出先于beforeunload及create/run被替代的顺序均须覆盖。真实准备错误、120秒超时、清理/保存失败仍须报错保存，不能因随后关窗掩盖。取消请求、实际清理完成、原生窗体销毁分别取证。v4本次真实清理及事后无占用已记录，v5当前为40组本地模型通过，实际候选提示/第二视频重开未验；预算和正式模块不变。

## 证据、执行冻结与交付

缓存可正常清理，不为复算旧性能重建它。`audit-host <runId> --recorded-frames`仅在原缓存目录缺失时允许从保存轨迹完整一致frameIds复算，仍验证协议/摘要引用/源SHA/源码；liveManifestVerified=false，不宣称当前manifest/PTS/像素或全部资产再验证。原目录存在但损坏、帧参考缺失/不一致时拒绝；默认审计维持实时清单要求。性能数值复算与独立源帧准确性验收分开。

测试入口独立于产品：使用独立脚本/测试接线和外部操作说明，正式UI不添加模式、生成、性能脚本或证据保存按钮。现有原型检查只作历史/复用参考，本轮不运行旧测试、FFmpeg或Eagle，不覆盖prototypes。

T0专项授权前固定：本次代码与任务范围、样本ID/指定路径/SHA/规格、参考方法、轨迹/种子与超时、缓存及临时目录、执行顺序/重复次数、进程归属、证据新根/单文件和总配额、可安全清理清单及保护哨兵。未固定/未获授权的项目不得开始；后续T1～T4也按各自范围固定，不将T0风险结论自动推广为产品验收。
