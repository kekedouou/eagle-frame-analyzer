# 验证协议与验收映射：阶段 3C

日期：2026-10-11。依据：[产品规格 v1](product.md)、[已批准架构 v1](architecture.md)、[A](experiments/A/report.md)、[B](experiments/B/report.md)、[S1](experiments/S1/report.md) 既有报告。

用户已批准两项 3C 决策：本文件的性能协议与资源观察停止线；优先使用用户指定的真实视频，缺项再安排合成。3C 文档落实后仍待用户最终验收，**不是产品实测通过，也未授权 T0 实验、阶段 4 开发或素材库写入**。以下重复次数、采样、统计和测试分组是 3C 执行细化，不改变产品功能、编码范围或架构。

## 分层与任务入口

验证分三层：L1 为纯逻辑/模拟，检查状态、索引、预算和故障；L2 为隔离文件/实际媒体检查，使用现有工具和专门输入；L3 为真实 Eagle 窗口与用户人工操作。L1/L2 不能代替 L3；提交画面不能代替屏幕物理呈现，用户观察不能写成 Codex 亲自执行。

层级描述运行环境，以下五类描述测试性质，可以交叉引用但不能互相代替。执行者均指后续获授权后的分工，本轮尚未执行。

| 性质 | 检查对象 / 层级 | 执行与判断来源 |
| --- | --- | --- |
| 单元 | 纯函数、状态/请求、索引/预算规则 / L1 | Codex运行隔离自动检查，明确模拟依赖 |
| 集成 | 模块接线、文件、进程、实际媒体与输出 / L1/L2 | Codex运行获授权的本地检查；模拟Eagle接口不冒充真实宿主 |
| Eagle宿主 | 实际API、窗口/运行时、播放音频及再次调用 / L3 | 用户加载和操作Eagle；Codex可只读审查真实记录，不写成亲自操作 |
| 性能 | 定时请求、画布提交、首次等待、资源趋势 / L2/L3 | 获授权的独立脚本自动计时；真实窗口由用户启动，Codex复核统计及范围 |

## 公共环境、起止与请求口径

执行前固定代码提交、工具版本、Windows/Eagle/Node/Chrome、CPU/GPU/RAM、缓存磁盘和实际路径、显示器刷新率/窗口尺寸、素材身份/SHA/规格、音轨/时间原点、后台负载及核对开关。以真实 Eagle 前台窗口为性能验收环境，不用本机 Node 模拟替代。

三种状态分开：无有效插件缓存的首次生成；磁盘缓存已有但解码 RAM 重置；已明确预热的 RAM 工作集。重置内容与有限预取须记录；未清除 Windows 文件缓存就不能称操作系统冷缓存。样本顺序/种子固定，轮次间重置方式一致；不以暖缓存成绩替换冷解码成绩。

每次操作至少记录会话/库/素材代次、原始输入号及时间、操作类别、目标帧/时间、有效目标、读取/解码开始和就绪、绘制提交、刷新机会、终态与原因。类别包括拖动、释放、明确时间定位、前后逐帧和标注点击定位；正常播放的时钟采样另列，不当作鼠标定位请求。

原始输入最终分别归为已提交、已显示目标复用、被新目标取代、取消、失败或轮末仍未完成。记录同帧合并及其关联，不能双计原始输入与有效目标；复用已显示画面但没有新绘制时，记录事实，不伪造 draw 或零毫秒绘制响应。计数应能核对总输入；测试超时计失败，保存未完成数量及等待时长，不删除该轮或给未完成请求填零延迟。

每轮分别报样本数、平均/P50/P95/最大值，P95 取排序后第 `ceil(0.95N)` 个值；跨轮汇总只能补充，不能代替每轮判定。性能从原始输入处理入口计至该目标 `drawImage` 提交，包含排队；同时分记读取、解码、就绪到提交。提交、rAF 刷新机会与屏幕实际呈现不同，物理呈现未可靠测得则留空。

## P-01/P-02：正常轮、压力轮与释放

- 正常快速拖动：每样本、每约定缓存条件 **3 轮，每轮 30 秒**。固定脚本混合往返、反转和随机跳转，使目标源帧充分变化，记录不同目标比例，避免大量同帧输入制造轻负载；慢拖/静止只检查正确性和响应，不套用55次/秒门槛。计划输入频率约 120 次/秒，记录实际间隔和数量。统计窗口为首次输入到固定 30 秒窗口结束；释放请求在之后单列，不能靠延长等待稀释停顿。轮首/轮尾尚无提交的区间也计入最长无提交。
- 正常快速目标变化的每轮画面提交率 **≥55 次/秒、最长无提交≤100ms**，是用户批准的 3C 工程验收门槛。显示配置不具备约60Hz或窗口确实后台节流时，记录条件不足并重新约定环境/补测；代码导致的刷新变慢仍属测试结果，不能作为环境借口筛掉。普通播放按源帧 PTS 展示，低源帧率播放不受 55 次/秒要求，不补帧或空重绘。
- 只计真实画布提交，输入/请求/就绪数不能充当更新率；按架构每个刷新机会至多提交一个最新目标，同一刷新机会内多次提交不能累计凑更新率，另记为调度异常。同帧重复与不同帧提交分别列出；合法重复目标可以复用，不能用无新输入的重绘循环凑数。每次提交前对照最新目标/代次与请求关联，任何陈旧目标提交均失败，不以较高更新率抵消。
- 独立定位：每样本、每约定缓存条件 **3 轮，每轮 200 个固定随机目标**，逐次等待完成，避免连续同目标。逐帧/标注点击等操作类别各自报告，样本不足时保留全部结果并标明，不能借大样本拖动平均掩盖某类失败。连续脚本的 P95 只描述完成请求，必须同时报告取代比例、未完成、排队、最长无提交和人工跟手。
- 在 T0 代表样本上，另做 **0/25/60ms 解码延迟注入，各 3 轮**，每轮解码 RAM 起点一致、使用相同序列；只对真实发生的未命中解码加延迟，记录注入范围。0ms作为正常基线按P-01/P-02门槛判定；25/60ms人为压力轮检查最新目标正确、安全和有限结束，并完整报告更新率/停顿，不要求注入60ms后仍满足正常50ms门槛。压力结果不混入正常通过统计，也不能作为正常未达标的豁免。S1 对应成绩为 61.77/32.39/18.04 次/秒，完成 P95 为 8.0/6.5/7.1ms，最长无提交为 69.5/180.3/444.2ms；末次正确不等于已解决饥饿。
- 每轮释放到稳定目标后，实际画布必须准确显示该源帧并保持暂停，之后才允许播放/添加标注；记录释放输入至实际提交及有限超时结果。旧请求都须明确结束，不能留下悬挂任务。有限超时值和轨迹在 T0 执行清单固定，超时属于失败，不构成响应标准豁免。

## P-03：首次与复用

每样本 **3 次首次完整准备、3 次有效缓存复用**，保留每次结果。首次前只处理专项授权目录内该样本的插件缓存，不改源文件、不清系统缓存、不碰旧证据。复用验证不重复生成；首次与复用不合并求平均。

起点为本次 `onPluginCreate`/再次调用回调或显式读取按钮入口，包含当次初始化、选中 API、排队、读取/哈希、分析、JPEG/音频生成及浏览器初始化；终点为完整缓存/索引、音频可用、首帧提交并可操作。无音轨时明确记音频不适用。预先准备好测试输入，制作样本耗时不计入插件准备；Eagle 进入回调前的启动未测须说明，不能冒充用户点击起的完整时间。

媒体时长沿实际共同时间关系确定，保留视频/音频跨度及容器记录，不随测量成绩改分母。原 B 的 6.73 秒为生成阶段；S1 原 4K 的 7848.3ms 为 Node 准备，3650.4ms 为窗口复用，均不能替代新缓存的完整窗口 P-03。真实 HEVC 首次 2478.2ms/约10.031秒支持已测案例，不代表 4K60 全矩阵通过。

## P-04：预算、趋势与观察停止线

受管 RAM 在每次分配、复制、预留与释放时登记，持续 **≤512MiB**，涵盖图像、音频、压缩读取及在途占额；不可取消的解码真正结束前不能归还。磁盘 **≤5GiB** 计完整/临时产物、JPEG、PCM、索引和清单，写入前预留、落盘后核对实际文件字节。小预算注入可检查分支，但模拟额度或稀疏文件不能宣称真实 5GiB 文件写满测试已完成。

插件可归属进程、FFmpeg、独立核对/测试辅助进程及 GPU 分列；记录 PID、父子关系和归属范围，不把整个 Eagle 内存擅自算作插件，也不漏掉已确认的插件进程。约 **100ms** 采样 RSS，注明短任务漏采、峰值可能漏测及不同步范围；各进程历史峰值不能相加冒充同时总峰值。S1 受管峰值510.06MiB与插件RSS峰值737.46MiB的口径不同，512MiB不是整个进程上限。

CPU在可取得进程累计CPU时间时同步记录插件可归属集合、单个FFmpeg和辅助进程的区间用量：`CPU时间增量/墙钟区间×100%` 表示一个逻辑核为100%，多线程可能超过100%；若改按整机逻辑核数归一化则单独列出并写明核数，不能混用。无法归属共享宿主、GPU或无法取样的部分标未测，不新增CPU产品门槛。

长时检查 **2 轮，每轮60分钟**，使用固定素材集合和工作循环，涵盖持续拖动、播放/暂停/逐帧及视频切换；各轮独立启动，按阶段标注负载与静置，避免用刚切换/刚生成的峰值比较空闲基线。比较每轮第10～15分钟与第55～60分钟相同负载窗口的RSS中位数；增量超过 **max(64MiB，基线10%)** 时不能直接验收，需查因/复测，不把该阈值当泄漏证明。60分钟结束后另静置5分钟观察资源收回，静置数据不替代第55～60分钟负载窗口。

测试观察停止线：可归属插件的进程集合同时RSS合计 **1.5GiB**，单个FFmpeg进程 **1GiB**。达到/超过时停止当前测试输入、使会话失效、停声并释放本次会话资源，安全停止/等待属于本次任务的预处理；保全异常与清理结果，不强杀共享 Eagle 或无归属进程。归属集合在 T0 执行清单固定，辅助核对进程另计；无法隔离共享宿主/GPU时单列，不能据此判总体内存达标。停止线是测试保护，**不是产品资源预算或操作系统硬限额**；100ms观测不能保证阻止瞬间超限。趋势异常或停止线触发的轮次保留为未通过/待查，不从统计消失。

| 缺项边界输入 | 真实视频优先；仍缺则T0列明并另获授权后制作少量合成/纯索引夹具 | 负/提前音频、音频先结束、VFR首末边界；重复/异常PTS先用逻辑夹具，不假定编码容器必保留人为PTS |

独立准确性先使用作者预先定义的帧编号/时间，不从插件输出反推期望。三段短合成遍历全部帧，检查首末、相邻逐帧、VFR边界前/正好/后、同帧重复输入及最终释放；核对实际画布像素。条码核对开/关分别记录，不能忽略GPU读回开销。

真实素材另从源文件建立独立顺序解码参考，不读插件缓存/索引来生成期望；每样本至少100个固定目标并覆盖首末/相邻候选。全部源帧数量、呈现顺序和缓存可访问性须全量核对，100个目标是像素抽查，不宣称全部真实帧像素都已核对。JPEG有损，帧身份与颜色/细节损失分别检查，不能要求源像素哈希相等，也不能仅以相似图哈希断言相邻源帧准确；无法区分的静态帧标为不确定并补参考。参考生成方法、时间对应和核对阈值在T0前固定，不为使结果通过回写期望。

## 人工体验与极简验收

T1 即按真实用户流程检查，不先堆实验控件再等 T4 清理。打开后自动准备，进度和失败原因可理解；就绪首帧暂停，播放、拖动和逐帧共用同一时间轴；鼠标释放后稳定停在正确画面，声音及时停止；文字标注步骤与固定画面一致。正式界面不出现样本/延迟/性能测试、模式切换、手动生成缓存或刷新标注按钮。

源图与 720p 预览核对比例、方向、裁切和可见色彩；播放与拖动维持相同预览质量。帧身份准确与 JPEG 压缩造成的细节差异分开记录；若关键动作或特效细节已妨碍分析，记录用户判断并调查，不用较快提交率替代画质验收。已有声画人工结果保留为原案例证据，正式版本检查改动后的使用流程，不回填旧报告。

## 证据、执行冻结与交付

测试入口独立于产品：使用独立脚本/测试接线和外部操作说明，正式UI不添加模式、生成、性能脚本或证据保存按钮。现有原型检查只作历史/复用参考，本轮不运行旧测试、FFmpeg或Eagle，不覆盖prototypes。

T0专项授权前固定：本次代码与任务范围、样本ID/指定路径/SHA/规格、参考方法、轨迹/种子与超时、缓存及临时目录、执行顺序/重复次数、进程归属、证据新根/单文件和总配额、可安全清理清单及保护哨兵。未固定/未获授权的项目不得开始；后续T1～T4也按各自范围固定，不将T0风险结论自动推广为产品验收。

新证据使用单独的有界根，例如项目内 `verification-runs/<run-id>/`，具体路径/配额须在授权前固定，未批准前不创建。测试插件的实际 `plugin.path` 置于批准的非C隔离根，缓存和partial仍位于其cache内、与插件同盘并核对所有权，不设C/TEMP例外。不得继续挤入旧S1 evidence、自动扩大32MiB旧限额、覆盖/删除历史记录。S1报告所记剩余额度18,917字节是2026-10-10快照，不冒充当前重新测量。

每次运行保存环境/样本/代码指纹、协议版本、入口与起止、逐轮统计、请求分类/异常、连续预算峰值、进程采样范围和用户人工字段；相同会话累积快照按会话身份去重，保留最终完整版本及先前失败。长时日志按有界聚合与异常滚动窗口保存，提前估算容量；额度不足停止记录/测试并标不完整，不能静默截断后判通过，不为省配额删除失败。

T4在同一候选代码提交、冻结样本和约定环境下汇总全部R/P，逐项标通过、失败、不适用或未验证，引用原始证据。T0/T1局部通过、模拟通过、架构批准、用户一次人工观察均不代替T4。若指标未满足，定位读取/解码/调度/绘制或资源原因后再决定修正，不自行降画质、删源帧、取消声音、改普通播放或扩大输入限制。
